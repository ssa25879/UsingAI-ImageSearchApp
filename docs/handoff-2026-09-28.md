## 현재 구현

UI Toolkit 검색 화면은 `SearchScreenPresenter`를 통해 Domain Repository 인터페이스에 의존한다. `ImageSearchCompositionRoot`가 검색 Repository, 썸네일 Repository, Presenter를 조립해 화면에 주입한다. Presentation은 Data 구현이나 DTO를 직접 참조하지 않는다.

Unity Editor 실행 시 `UserSettings/ImageSearch/pixabay.key`에 유효한 키가 있고 Inspector의 `Force Mock`이 꺼져 있으면 실제 Pixabay 검색 DataSource와 HTTP 썸네일 DataSource를 사용한다. 키 파일이 없거나 비었거나 읽을 수 없으면 경고 로그를 남기고 앱 실행용 Mock을 사용한다. `Force Mock`을 켜면 키가 있어도 Mock을 사용하므로 `Mock Search Scenario`에서 성공, 빈 결과, 연결 실패, 서버 오류 화면을 확인할 수 있다. 모바일 빌드는 키를 포함하지 않으며 Mock으로 실행한다.

실제 검색 요청은 `https://pixabay.com/api/`를 사용한다. 검색 응답은 `UserSettings/ImageSearch/Cache/`에 24시간 캐시하고, DataSource 인스턴스에서 60초에 최대 100회 요청을 허용한다. HTTP 요청과 썸네일 다운로드는 15초 타임아웃을 적용한다. 이미지는 결과 화면에서만 URL로 내려받고 이미지 바이트를 영구 저장하지 않는다. 실제 결과에는 `이미지 제공: Pixabay`를 표시한다. 관련 기준은 [Pixabay API 문서](https://pixabay.com/api/docs/)를 참조한다. 분당 요청 제한은 앱 인스턴스 기준이므로 여러 클라이언트가 같은 키를 쓰는 운영 서비스에서는 서버에서 키와 요청량을 관리해야 한다.

취소는 DataSource에서 `UnityWebRequest`를 중단하고 `OperationCanceledException`을 다시 전파한다. Repository는 예상 네트워크/HTTP 실패를 `Result`의 `NetworkError`로 매핑하며 취소를 일반 실패로 바꾸지 않는다. Presenter는 새 검색 때 이전 요청을 취소하고 작업 세대 번호로 늦게 도착한 이전 결과를 버린다. 기존 카드와 소유 Texture는 결과 교체 및 화면 파괴 시 해제한다.

## API 키와 보안

- 팀원 설정 방법은 루트 `README.md`에 있다. 키 문자열은 채팅, 소스, 로그, 문서에 기록하지 않는다.
- `.gitignore`가 `UserSettings/`와 `/UserSettings/ImageSearch/pixabay.key`를 제외한다. 이전 작업에서 키 파일이 `git status`에 나타나지 않고 `git check-ignore`로 무시되며, 당시 커밋 기록에 로컬 키 문자열이 없음을 확인했다.
- Editor 전용 로컬 키 방식은 개발용이다. 모바일 실제 서비스에서는 키를 서버에 보관하고 앱이 자체 서버 API를 호출하도록 바꿔야 한다.

## 테스트와 검증

- EditMode: 총 53개 통과. 기존 Core/Domain/Data/Presentation 테스트에 키 로더, 검색 캐시, 요청 제한, 썸네일 Repository 테스트를 추가했다. 테스트는 실제 네트워크와 실제 키를 사용하지 않는다.
- PlayMode: 전용 `ImageSearch.Presentation.PlayModeTests.asmdef`에서 8개 통과. 테스트가 화면 fixture와 응답 제어용 Mock Repository를 직접 구성해 실제 검색 DataSource를 사용하지 않는다. UI `TextField`와 `Button`을 통해 검색하고, 조건 대기와 5초 타임아웃으로 화면 변화를 확인한다.
- PlayMode 시나리오: 첫 화면, 검색 성공과 카드 텍스트, 빈 결과, 연결 실패, 서버 오류, 빈 검색어, 재검색 시 카드 교체, 빠른 연속 검색 시 마지막 결과만 표시.
- 실제 Play 모드에서 `cat`을 검색해 결과 20개와 실제 썸네일 표시를 확인했다. 스크린샷은 `Temp/pipeline-screenshots/actual-pixabay-cat-final.png`다. `Temp/`는 Git 무시 대상이므로 전달이 필요하면 별도로 복사해야 한다.
- 위 수치는 실제 연결 작업 완료 시점의 검증 결과다. 이 인수인계 문서 수정 뒤 테스트는 다시 실행하지 않았다.

## 검증 재실행

Editor가 PlayMode이면 먼저 중지한다. 이전에 PlayMode 중 EditMode 테스트를 실행했을 때 씬 복원 오류가 발생했다. Unity CLI 작업은 프로젝트의 `unity-cli` 스킬 절차를 따른다.

```powershell
& "$env:LOCALAPPDATA\Unity\bin\unity.exe" status --project-path "D:\work\image-search" --format json
& "$env:LOCALAPPDATA\Unity\bin\unity.exe" --format json command editor_stop --project-path "D:\work\image-search"
& "$env:LOCALAPPDATA\Unity\bin\unity.exe" recompile --project-path "D:\work\image-search" --timeout 180 --format json
& "$env:LOCALAPPDATA\Unity\bin\unity.exe" --format json command run_tests --project-path "D:\work\image-search" -- --mode editor --async_tests false --timeout 300
& "$env:LOCALAPPDATA\Unity\bin\unity.exe" --format json command run_tests --project-path "D:\work\image-search" -- --mode playmode --async_tests true --timeout 300
```

PlayMode 테스트가 비동기로 시작되면 Unity CLI의 `command test_status`로 완료 결과를 확인한다. 실제 Pixabay 검색은 키가 있는 로컬 Editor에서만 수동 확인한다.
