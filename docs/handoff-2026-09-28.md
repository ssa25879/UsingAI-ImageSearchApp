## 구현 요약

UI Toolkit 검색 화면은 `SearchScreenPresenter`를 통해 Domain의 `IImageSearchRepository`와 `IImageThumbnailRepository`에 의존합니다. `ImageSearchCompositionRoot`가 DataSource, Mapper, Repository 구현을 조립하고 Presenter에 주입합니다.

Editor에서 `Force Mock`을 켜거나 로컬 키를 찾지 못하면 Inspector 시나리오를 제공하는 Mock 검색 DataSource와 Mock 썸네일 Repository를 씁니다. 키가 있고 `Force Mock`이 꺼진 Editor 실행에서는 Pixabay 검색 및 HTTP 썸네일 DataSource를 씁니다. 모바일 빌드는 로컬 키를 사용하지 않아 Mock 경로로 동작합니다.

검색 응답은 24시간 로컬 캐시를 사용하고, DataSource 인스턴스 내 요청 창은 분당 최대 100회를 허용합니다. HTTP 요청과 썸네일 요청에는 15초 타임아웃을 적용합니다. 검색 오류는 `NetworkError`로 매핑합니다. 이미지 바이트는 화면에서 Texture2D로 디코딩하며, 카드 교체 또는 화면 파괴 시 소유 텍스처를 해제합니다.

## 실행 방법

1. Unity Hub에서 프로젝트를 Unity `6000.3.19f1`로 엽니다.
2. `Assets/UI/ImageSearch/Scenes/ImageSearchPreview.unity`를 엽니다.
3. Play를 눌러 화면을 실행합니다.
4. Mock 동작은 `Image Search Screen` 오브젝트의 `Image Search Composition Root`에서 `Force Mock`을 켜고 `Mock Search Scenario`를 선택합니다.

**빌드 제한:** `ProjectSettings/EditorBuildSettings.asset`에는 `Assets/Scenes/SampleScene.unity`만 활성화되어 있습니다. 모바일 빌드의 시작 장면에 검색 UI가 들어가도록 Unity Editor의 Build Profiles에서 검색 화면 씬을 추가해야 합니다. 씬 YAML을 직접 편집하지 않습니다.

## API 키와 보안

현재 Editor 구현은 `UserSettings/ImageSearch/pixabay.key`에서 키를 읽습니다. 파일은 `.gitignore`에서 제외되어 있지만 프로젝트 내부에 있습니다. 이는 `AGENTS.md`가 정한 프로젝트 외부 안전 저장소 또는 환경 변수 주입 규칙과 다를 수 있습니다. 다음 세션에서 팀/CI 사용 전에 로더를 외부 경로 또는 환경 변수 입력을 지원하도록 바꾸거나, 허용 예외 범위를 규칙에 명확히 해야 합니다. 키 문자열은 소스, 씬, 로그, 커밋, 문서에 쓰지 않습니다.

운영 모바일 앱에 Pixabay 키를 넣지 않습니다. 서버 측 키 보관과 앱 자체 API를 통한 검색이 필요합니다. Pixabay 출처 표기와 사용 조건은 [공식 API 문서](https://pixabay.com/api/docs/)를 확인합니다.

## 테스트와 마지막 기록

마지막 구현 검증 기록에는 컴파일 오류 0건/경고 0건, EditMode `53/53`, PlayMode `8/8` 통과라고 되어 있습니다. 이번 문서 갱신에서는 Unity 컴파일과 테스트를 다시 실행하지 않았으므로, 이후 코드 변경이 있다면 결과를 재확인해야 합니다. 테스트는 실제 네트워크를 호출하지 않습니다.

Unity Test Runner는 **Window > General > Test Runner**에서 열고 EditMode와 PlayMode를 각각 실행합니다. Unity CLI를 사용할 경우 프로젝트 루트에서:

```powershell
unity test . --editor-version 6000.3.19f1 --mode EditMode --timeout 600
unity test . --editor-version 6000.3.19f1 --mode PlayMode --timeout 600
```

최근 구현 테스트는 첫 화면 안내, 성공/빈 결과/연결 실패/서버 오류, 빈 키워드, 카드 교체, 빠른 재검색의 늦은 결과 무시를 확인합니다. 실제 HTTP 통합 검증은 이 테스트에 포함하지 않습니다.

## 리뷰에서 확인한 미해결 항목

1. **빌드 진입 씬:** Build Settings에는 `SampleScene`만 있습니다. 검색 UI 씬을 Build Profiles에 등록해야 실제 빌드에서 검색 화면으로 시작합니다.
2. **취소 예외 규칙:** `Assets/UI/ImageSearch/Runtime/SearchScreenPresenter.cs`의 `SearchAsync`와 `LoadThumbnailAsync`는 `OperationCanceledException`을 catch하고 삼킵니다. 이는 `AGENTS.md`의 취소 전파 규칙과 충돌하므로 정리할 필요가 있습니다.
3. **썸네일 성공 경로 테스트:** 현재 Presentation 테스트의 썸네일 Fake는 오류 결과를 반환합니다. PNG 디코딩 성공, `SetThumbnail`, 지연된 썸네일 취소, Texture2D 교체/해제 테스트가 빠져 있습니다.
4. **Composition Root 테스트:** 키/Force Mock 조합별 구현 선택과 출처 표시가 자동화되어 있지 않습니다.
5. **페이지 로드:** 화면은 1페이지 20개만 요청하며 다음 페이지 로딩을 구현하지 않았습니다.
6. **API 키:** 현재 Editor 키 파일은 프로젝트 로컬 `UserSettings`에 있습니다. 보안 규칙과 일치시키는 입력 방법이 필요합니다.
